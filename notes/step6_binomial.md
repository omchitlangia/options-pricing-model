Part 1 — Motivation for Binomial Benchmarking
Testing only Black–Scholes is not enough because if we see pricing errors, we don’t know whether the problem comes from the model’s assumptions (like constant volatility and lognormal returns) or from how we computed prices numerically. We need a second, independent pricing framework to separate these effects. The binomial model helps resolve the doubt of whether the mispricing is due to Black–Scholes’ structural assumptions or due to implementation or numerical approximation issues. Since the binomial model prices options through step-by-step price paths instead of a closed formula, it serves as a practical benchmark. If binomial prices agree with Black–Scholes but both disagree with market prices, the error is structural. If binomial and Black–Scholes disagree strongly, the issue may be numerical or implementation-related.

Part 2 — Core Idea of the Binomial Model
At each step, the binomial model assumes the underlying price can move only in two ways: it either goes up by a fixed factor or goes down by a fixed factor. So instead of continuous movement, price evolves through small up/down jumps step by step. Time is handled differently from Black–Scholes because it is broken into many small discrete intervals instead of being treated as continuous. The option value is built by moving through these small time steps and working backward from expiry to today. The model is called a recombining tree because different price paths can lead to the same future price level. For example, an up move followed by a down move reaches the same node as a down move followed by an up move. The branches “recombine,” which keeps the tree compact and computationally efficient. 

Part 3 — No-Arbitrage Replication in One Step
An option is replicated in one step by constructing a portfolio of stock and borrowing/lending that produces the same payoff as the option in both the up and down price states. The number of shares and the cash position are chosen so the portfolio payoff exactly matches the option payoff in each case. We match payoffs in both up and down states because those are the only possible outcomes in the one-step model. If payoffs differed, arbitrage would be possible by buying the cheaper payoff and selling the more expensive one. Once the replicating portfolio is built, today’s option value equals the cost of setting up that portfolio today. By no-arbitrage, two positions with identical future payoffs must have the same present value.

Part 4 — Risk-Neutral Probability
Risk-neutral probability comes from the no-arbitrage rule. It is chosen so that the expected future stock price grows at the risk-free rate, which keeps pricing internally consistent. It is not a real-world probability because it is not based on historical data or prediction. It is only a pricing weight used inside the model. It enforces the no-arbitrage condition — meaning discounted expected payoffs can be used to correctly price options.

Part 5 — Multi-Step Tree & Backward Induction
We extend one-step replication to many steps by building a binomial price tree over multiple time intervals. At each step, the stock can move up or down, and the same no-arbitrage pricing logic is applied step-by-step instead of just once. At the terminal nodes (final time step / expiry), we compute the option payoff directly from the payoff formula (for example, max(S − K, 0) for a call). These are known values — no modeling needed there. Backward induction means we then move backward through the tree from expiry to today. At each earlier node, the option value is found by taking the discounted expected value of the next-step node values using risk-neutral probability. Repeating this step-by-step gives the option price today.

Part 6 — Parameterization Using Volatility
In the binomial model, the up and down move sizes are linked to volatility so that each step’s price movement reflects how volatile the underlying is. Higher volatility means larger up/down jumps per step. We use the CRR (Cox–Ross–Rubinstein) specification where the up factor is u = exp(σ√dt) and the down factor is the inverse. This choice keeps the tree symmetric and makes the step size directly controlled by volatility and time step length. The key property being matched is the variance (volatility) of returns. The CRR setup ensures that as the number of steps increases, the tree’s return variance matches the continuous-time volatility used in Black–Scholes.

Part 7 — European vs American Capability
The binomial model can price American options easily because it evaluates the option value at every node in the time tree, not just at expiry. Since the model already computes values step-by-step backward, it can naturally handle the possibility of early exercise. The extra check added at each node is: compare the exercise value (value if exercised immediately) with the continuation value (value of holding the option based on future nodes). The option value at that node is taken as the higher of the two. Closed-form Black–Scholes generally cannot do this because it assumes exercise only at expiry and produces one direct formula for the final payoff case. It does not evaluate intermediate nodes, so it cannot handle early-exercise decisions except in a few special cases. 

Part 8 — Empirical Implementation Choice
European calls were used in the binomial implementation to keep the contract type consistent with the Black–Scholes model, which is derived for European-style options. This makes the comparison between binomial and Black–Scholes prices fair and model-to-model rather than contract-to-contract. Implied volatility was used as the input instead of historical volatility because it reflects the volatility currently priced by the market for each option. Using implied volatility keeps the binomial pricing aligned with observed market expectations rather than past realized movement. Volatility input was kept consistent across models to ensure that any pricing differences come from the model structure and numerical method, not from different parameter assumptions. This isolates model effects and makes the benchmarking meaningful.

Part 9 — Empirical Results
The binomial model using implied volatility produced a very low mean absolute pricing error (≈ 0.0034), indicating very close agreement with market prices overall. Across moneyness buckets, binomial pricing errors were small and did not show strong directional bias like earlier Black–Scholes results. Errors stayed close to zero for OTM, ATM, and ITM options. There was no visible structured mispricing pattern across strikes or maturities. Errors appeared random and centered near zero, supporting the conclusion that earlier pricing errors were due to the constant-volatility assumption, not numerical method issues.

Part 10 — Interpretation of Results
The near-zero binomial pricing error implies that the earlier Black–Scholes mispricing was not caused by numerical computation issues. It points instead to model input assumptions — especially the volatility specification — as the main source of the earlier structured errors. Changing the numerical engine by itself does not remove pricing structure or bias. When the same volatility assumption is used, different numerical methods tend to agree. The big improvement came from switching to implied volatility, not from switching formulas to a tree. The variable that actually drives pricing accuracy is the volatility input. Using market-implied volatility aligns model prices with observed prices, while using a fixed or historical volatility creates systematic mispricing regardless of the numerical method used.
